---

## 🎯 1. Назначение

Документ фиксирует: где живёт текст системного промпта, как он загружается, как
оператор меняет его в runtime, и что попадает в аудит. Промпт определяет тон и
стиль ответа, который воркер генерирует на каждый отзыв.

Ключевое архитектурное решение: **промпт — отдельный файл-SOT** на shared volume,
а не поле в `config.json` и не захардкоженная строка в коде. Это позволяет править
тон ответа через `/admin` без деплоя новой версии.

---

## 🧩 2. Состав промпта-SOT

Промпт — единый текст (не multipart), хранящийся в трёх уровнях источника:

| Уровень | Источник | Назначение | Когда используется |
|---------|----------|-----------|--------------------|
| **Вшитый default** | `worker/prompt_loader.py:_BUILTIN_DEFAULT` | Строка-заглушка в коде | Если нет ни shared-файла, ни `prompts/v1/system.md` (аварийный fallback) |
| **Вшитый промпт v1** | `worker/prompts/v1/system.md` | Канонический текст промпта, вшит в образ | Bootstrap: копируется в shared-файл при первом запуске |
| **Shared-файл (SOT)** | `/data/runtime/system_prompt.md` (volume `runtime-config`) | **Единственный источник истины в runtime** | Каждый цикл опроса воркера; `/admin` перезаписывает его |

> 📌 После bootstrap единственный SOT — shared-файл. Вшитый `prompts/v1/system.md`
> больше не читается в runtime; он нужен только для первого копирования и как
> эталон для восстановления.

---

## 🧠 3. Текст промпта (v1)

Канонический текст из `worker/prompts/v1/system.md`:

```text
# System prompt — генерация ответа на отзыв (v1)

Ты помощник поддержки, который отвечает на отзывы и комментарии клиентов на русском языке.

Отвечай на каждый входящий текст: позитивный, негативный, нейтральный, короткий или эмоциональный.
Сформируй естественный, вежливый и уместный ответ от лица компании.

- Если текст негативный — извинись и предложи помочь.
- Если текст позитивный — поблагодари.
- Если текст нейтральный — коротко отреагируй по существу без просьбы обязательно что-то уточнять.

Не используй markdown, канцелярит, шаблонные фразы и подписи. Не повторяй отзыв дословно.
Ответ должен быть на русском языке и не длиннее 3 предложений.
```

> 📌 Промпт **не содержит плейсхолдеров** — тон определяется отдельно словарём
> маркеров (без LLM), и промпт получает уже классифицированный контекст. Тон
> ответа задаётся текстом промпта по смыслу входящего отзыва, а не отдельной
> переменной.

## 📁 4. Версионирование

Вшитые промпты лежат в `worker/prompts/v1/`. Каталог `v1` — версия промпта,
вшитого в образ. Это позволяет при необходимости выпустить `v2` рядом и
переключить bootstrap-источник, не трогая `v1`. В runtime версия не используется —
воркер читает только shared-файл.

## 🔄 5. Lifecycle промпта

### 🚀 5.1. Bootstrap (первый запуск)

При старте воркер вызывает `bootstrap_prompt()` (`worker.py`):

1. Проверяет, существует ли shared-файл `runtime_prompt_path`
   (`/data/runtime/system_prompt.md`).
2. Если **существует** — ничего не делает (не перезаписывает операторскую правку).
3. Если **нет** — копирует вшитый `prompts/v1/system.md` в shared-файл.
4. Если и вшитого нет — shared-файл остаётся отсутствующим; `_PromptCache` в
   runtime вернёт `_BUILTIN_DEFAULT`.

### ⏱️ 5.2. Загрузка и mtime hot-reload

`worker/prompt_loader.py:_PromptCache` — потокобезопасный mtime-кеш:

- `load_system_prompt()` вызывается на каждом цикле опроса перед генерацией ответа.
- Кеш хранит последний текст + `st_mtime` файла.
- Если mtime не изменился — возвращает кешированный текст (без чтения с диска).
- Если mtime изменился — перечитывает файл, логирует
  `System prompt reloaded from /data/runtime/system_prompt.md (N bytes)`,
  обновляет кеш.
- Если файл отсутствует — возвращает `_BUILTIN_DEFAULT`.

> 📌 Смена промпта применяется на **следующем цикле опроса** — без рестарта
> контейнера. mtime-проверка дешёвая (один `stat` на цикл).

### ✏️ 5.3. Правка через `/admin`

Оператор правит промпт в панели «Системный промпт» конфиг-консоли
(`site/app/api/admin.py`):

- `read_prompt_text()` — читает текущий shared-файл (для предзаполнения textarea).
- На `POST /admin` (сохранение, `require_admin` — demo → `403`):
  - `previous_prompt = read_prompt_text()`; `new_prompt = system_prompt.strip()`.
  - `prompt_changed = previous_prompt.strip() != new_prompt`.
  - Если `prompt_changed` — `write_prompt_text(new_prompt)` (атомарная запись).
  - Если не изменился — файл не трогается (`prompt_changed=False`).

## 🔧 6. Атомарная запись

`write_prompt_text()` (`admin.py`) записывает файл атомарно, чтобы воркер не
прочитал половину записи:

1. `path.parent.mkdir(parents=True, exist_ok=True)` — гарантирует каталог.
2. `tempfile.mkstemp(dir=parent, prefix=".prompt.", suffix=".tmp")` — временный
   файл в той же директории (одна файловая система → атомарный rename).
3. Запись текста во временный файл.
4. `os.replace(tmp, path)` — атомарная замена (POSIX `rename(2)`).
5. При ошибке — `os.unlink(tmp)` и проброс исключения.

> 📌 `os.replace` атомарен на одной ФС; временный файл в той же директории
> гарантирует, что rename не пересечёт файловые системы. Воркер либо видит
> старый промпт целиком, либо новый — никогда наполовину.

## 📊 7. Параметры LLM (runtime)

Параметры генерации настраиваются отдельно от промпта, в `config.json` (см.
[🎛️ OPERATOR_GUIDE.md](OPERATOR_GUIDE.md) §2):

| Параметр | Runtime-ключ | Per-провайдер | Назначение |
|----------|--------------|:-------------:|------------|
| Активный провайдер | `active_provider` | — | `openai` / `gigachat` |
| Fallback провайдер | `fallback_provider` | — | LLM-запас при сбое активного |
| Включён | `<prov>_enabled` | ✅ | Включает провайдер в цепочку fallback |
| Model | `<prov>_model` | ✅ | `openai_model` / `gigachat_model` |
| Base URL | `<prov>_base_url` | ✅ | OpenAI — редактируемый; GigaChat — read-only из `.env` |
| Temperature | `<prov>_temperature` | ✅ | Случайность генерации |
| Max tokens | `<prov>_max_tokens` | ✅ | Лимит длины ответа |

> 🔒 Сами LLM-ключи (`OPENAI_API_KEY`, `GIGACHAT_AUTH_KEY`) — **только в `.env`**,
> не в `config.json` и не в `/admin`. Воркер читает их из настроек, не из
> shared volume. В `status.json` пишутся только булевы флаги «сконфигурирован» —
> не значения ключей.

## 🛡️ 8. Аудит промпта

Событие `admin.config_update` (при `POST /admin`) пишет в `audit_logs` поля
промпта **без полного текста**:

| Поле | Что фиксирует |
|------|---------------|
| `prompt_len` | Длина нового промпта (символы) |
| `prompt_changed` | `true` / `false` — изменился ли текст |
| `changed_keys` | Список изменённых runtime-ключей (провайдер/модель/…, не промпт) |

> 🛡️ **Что НЕ попадает в аудит:** полный текст промпта, значения ключей LLM,
> значения токенов. Аудит показывает *факт* изменения и длину, но не *содержимое*.
> Это баланс между observability («кто и когда сменил тон ответа») и защитой
> чувствительного содержимого. См. [🛡️ SECURITY_NOTES.md](SECURITY_NOTES.md) §6.

---

## 🪟 9. Ридонли-мета в «Состояние системы»

`prompt_info()` (`admin.py`) возвращает ридонли-мета о файле промпта для блока
«Состояние системы» и `GET /admin/status`: `{source: "file", exists: bool,
size: bytes, mtime: iso}`. Это диагностика (есть ли файл, какого размера), не
содержимое.
