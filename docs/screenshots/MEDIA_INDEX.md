## 1. Правила нейминга

Формат: `RAR_{CATEGORY}_{DESCRIPTION}.{ext}`

| Категория | Назначение | Пример |
|-----------|------------|--------|
| `admin` | Операторская панель `/admin` (вход, конфиг, обсервабилити, аудит) | `RAR_admin_login.png` |
| `site` | Публичный сайт отзывов (форма, тред, демо-бейдж квоты) | `RAR_site_demo_badge.png` |
| `tg` | Telegram-уведомления оператору (внешний канал доставки) | `RAR_tg_review_notification.png` |
| `arch` | Архитектурные схемы (опционально, если Mermaid рендерится плохо) | `RAR_architecture_mermaid.png` |
| `demo` | Демонстрационные GIF/видео (опционально) | `RAR_demo_walkthrough.gif` |

## 3. Единый демо-контекст для скриншотов

| Параметр | Значение |
|---|---|
| Проект | Review Auto Responder |
| Площадка | `https://review-auto-responder.alex-n8n.site` (живое демо за Traefik, TLS) |
| Сайт отзывов | `https://review-auto-responder.alex-n8n.site/` |
| Операторская панель | `https://review-auto-responder.alex-n8n.site/admin` |
| LLM | GigaChat (`GigaChat-Max`) |
| Демо-лимит | `5` публикаций на демо-сессию (`POST /api/reviews`; 1 POST = 1 LLM-генерация) |
| Демо-доступ | Демо-токен (только просмотр) — одно-кликовой демо-вход; мутации → 403 |
| Полный доступ | Полный токен — смена провайдера/модели/промпта в runtime |

## 4. Правила добавления новых скриншотов

1. Использовать схему нейминга `RAR_{CATEGORY}_{DESCRIPTION}.png`.
2. Добавить строку в таблицу каталога.
3. Указать, в каких документах используется.
4. Не добавлять изображения без явного назначения.
5. Скриншоты UI/API только; архитектурные схемы — в Mermaid внутри Markdown.
6. В подписях не упоминать имена секретов (`ADMIN_TOKEN`, `ADMIN_DEMO_TOKEN`, `WORKER_API_TOKEN`) — только роли/назначение.
