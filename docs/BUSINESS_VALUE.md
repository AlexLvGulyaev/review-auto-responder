# 💼 BUSINESS_VALUE.md — Review Auto Responder

**Проект:** review-auto-responder
**Дата создания:** 2026-08-14
**Последнее обновление:** 2026-08-14
**Статус:** Портфельный актив — демо универсального паттерна «парсер + автономная AI-обработка 24/7».

> 📌 **Позиционирование:** проект демонстрирует не «ответчик на отзывы» как
> продукт, а **переиспользуемый паттерн** — автономный конвейер «сбор новых
> записей → классификация → AI-реакция → уведомление оператора», применимый к
> любой задаче, где нужно 24/7 реагировать на входящий поток. Отзывы — лишь
> один из примеров (см. §6).

---

## 🎯 1. Проблема

Команда поддержки получает отзывы через сайт. Без автоматизации:

### Со стороны бизнеса-заказчика (кому внедряют)

| Проблема | Последствие |
|----------|-------------|
| Отзывы мониторят вручную или не мониторят вовсе | Негатив висит часами/днями → отток клиентов, репутационный ущерб |
| На каждый отзыв отвечает человек | 24/7 невозможно вручную; ночью/в выходные — тишина |
| Оператор не видит негатив мгновенно | Упущен момент, когда клиент ещё лоялен и вопрос решаем |
| Один шаблон ответа на всё | Позитив и нейтрал получают неуместные «извинения»; негатив — шаблон вместо эмпатии |

### Со стороны интегратора (кто внедряет)

| Проблема | Последствие |
|----------|-------------|
| Нет готовой заготовки «опросчик + классификатор + AI-ответ + уведомление» | Каждую автоматизацию «сбор + AI-реакция» собирают с нуля |
| LLM-генерация дорога на каждом шаге | Классификация тона через LLM = лишние токены на каждый отзыв |
| Захардкожен один провайдер | Сбой/дороговизна провайдера останавливает систему |
| Промпт в коде | Любая правка тона/стиля ответа = деплой новой версии |

---

## 💡 2. Решение

Автономный AI-ассистент из двух сервисов:

- **Сайт отзывов** (FastAPI + PostgreSQL) принимает отзывы и хранит их как
  threaded-комментарии (модель `Review` с самоссылкой `parent_id`).
- **Обработчик** (воркер, asyncio-поллер) каждые N секунд забирает новые отзывы,
  определяет тон **словарём маркеров без LLM**, генерирует ответ нейросетью,
  публикует его дочерним комментарием от `AI Support` и шлёт уведомление оператору
  в Telegram. Негатив виден оператору мгновенно — и он подключается лично там,
  где автономный ответ не решает вопрос.

Архитектурные решения, создающие ценность:

- **Дешёвая классификация.** Тон определяется словарём маркеров — без LLM-вызова.
  Нейросеть включается только на генерации ответа. Это экономит токены и даёт
  предсказуемую классификацию.
- **Мультипровайдерность + fallback.** OpenAI / GigaChat через единую абстракцию
  Chat Completions; active → fallback LLM → словарные шаблоны. Система отвечает
  даже без LLM-ключей.
- **Промпт — файл-SOT.** `system_prompt.md` на shared volume; оператор правит его
  через `/admin` без деплоя; воркер подхватывает по mtime.
- **Runtime-config без рестарта.** Провайдер, модель, temperature, max_tokens,
  промпт меняются в `/admin` и применяются на следующем цикле опроса.
- **Демо-RBAC.** Полный токен (мутации) + read-only демо-токен (одно-кликовой
  вход, токен не попадает в браузер) — backend-guard на мутации.
- **Токенизированный демо-лимиттер.** Публичная форма ограничена квотой
  (5 LLM-генераций на сессию) — публичное демо не разорит на токенах.

## 💰 3. Количественная бизнес-ценность

> 📌 Все показатели ниже — оценочные, для демонстрации порядка величин.

### ⏱️ 3.1. Для заказчика-внедрения: время реакции на отзыв

| Показатель | Без автоматизации | С Review Auto Responder |
|------------|-------------------|------------------------|
| Время ответа на отзыв | Часы–дни (ручной мониторинг) | Секунды–минуты (автономно) |
| Покрытие вне рабочих часов | Нет | 24/7 |
| Время до уведомления оператора о негативе | Часы | Мгновенно (Telegram) |
| Доля отзывов с ответом | Частичная | 100% (включая fallback-шаблоны) |

### 🛠️ 3.2. Для интегратора: ускорение внедрения

| Показатель | С нуля | От этой базы |
|------------|--------|--------------|
| Готовый конвейер «сбор → классификация → AI-ответ → уведомление» | 1–2 недели | Настроить промпт + источник данных |
| Observability (логи, трейсы, аудит) | Своё решение | Три контура «из коробки» |
| Демо-RBAC админки | Своё решение | Готовый паттерн (два токена, backend-guard) |

### 💵 3.3. Стоимость одной обработки

| Статья | Стоимость |
|--------|-----------|
| Классификация тона | **0 токенов** (словарь маркеров) |
| Генерация ответа (GigaChat-Max, ~25 токенов ответ) | ~десятые доли копейки за отзыв |
| Fallback (без LLM-ключа) | 0 — словарные шаблоны по тону |

> 📌 Дешёвая классификация — ключевой экономический рычаг: тон определяется без
> LLM, нейросеть работает только ради самого ответа. Сравните с подходом, где LLM
> классифицирует тон **и** генерирует ответ — там каждый отзыв стоит 2× токенов.

### 📈 3.4. Масштабируемость

| Масштаб | Источник отзывов | Затраты |
|---------|------------------|---------|
| 1 сайт | Свои отзывы | 1 воркер, ~0 Cost |
| 10 сайтов | Несколько доменов | 1 воркер, общий цикл опроса |
| Маркетплейс | API продавца (официальный) | 1 воркер, опрос по расписанию |

## 🎯 4. Как создаётся ценность

- **Для оператора поддержки (энд-юзер):** негатив виден в Telegram мгновенно;
  рутина «поблагодарить за позитив / отреагировать на нейтрал» снята; человек
  фокусируется на негативе, где нужен личный контакт.
- **Для бизнеса-заказчика:** 24/7 покрытие, нулевое время ответа, ни один отзыв
  не висит без реакции; репутационный ущерб от «висящего негатива» устранён.
- **Для интегратора:** готовая заготовка паттерна «парсер + AI-обработка» —
  адаптировать источник данных и промпт, остальное (fallback, observability,
  демо-RBAC, лимиттер) уже есть.
- **Для потенциального заказчика AI-автоматизации (потребитель портфеля):**
  живое демо паттерна с публичным сайтом и операторской панелью — видно, как
  «сбор + AI-реакция 24/7» выглядит на практике, до заказа похожего.

## 🆚 5. Отличия от типовых решений

| Критерий | Ручной мониторинг | ChatGPT-чат оператора | Review Auto Responder |
|----------|-------------------|----------------------|----------------------|
| 24/7 автономный ответ | ❌ | ❌ (человек пишет) | ✅ |
| Классификация тона | Человек | LLM (платно) | Словарь (бесплатно) |
| Мгновенное уведомление о негативе | ❌ | ❌ | ✅ Telegram |
| Смена провайдера без деплоя | — | — | ✅ `/admin` runtime |
| Fallback без ключей | — | ❌ | ✅ словарные шаблоны |
| Демо-квота на публичную форму | — | — | ✅ |

**Где уступает:** автономный ответ — это не замена человеку на сложном негативе
(возврат денег, escalation). Это снятие рутины и мгновенный сигнал оператору.
Человек остаётся для случаев, где нужен личный контакт.

## 🚀 6. Сценарии применения (универсальный паттерн)

Паттерн «опросчик → классификатор → AI-реакция → уведомление» применим за пределами
отзывов:

- **Отзывы интернет-магазинов** на собственном сайте — базовый сценарий.
- **Отклики на фриланс-заказы** — скрипт собирает новые заказы, нейросеть
  проверяет соответствие навыкам и генерирует отклик за 10–15 секунд.
- **Обращения в форме обратной связи** — авто-ответ + эскалация негатива.
- **Любая задача «сбор новых записей + AI-реакция 24/7»** — отклики, заявки,
  комментарии, тикеты.

> ⚠️ **Реалистичная область:** собственные сайты и официальные API маркетплейсов
> (API продавца). Парсинг защищённых от ботов витрин (Ozon/Wildberries) — не
> целевая задача: защита от ботов ломает опросчик.

## 🏢 7. Целевые заказчики

- Интернет-магазины со своим сайтом отзывов.
- Сервисные компании, принимающие обращения через веб-форму.
- Фрилансеры/агентства, откликающиеся на поток заказов.
- Команды, которым нужен публично-демонстрируемый кейс AI-автоматизации «из коробки».

## ⚠️ 8. Риски и ограничения

| Риск | Влияние | Митигация |
|------|---------|-----------|
| Качество ответа зависит от промпта/модели | Среднее | Промпт-файл-SOT (правка без деплоя); версионирование; fallback; LLM-метрики в трейсах |
| Автономный ответ не решает сложный негатив | Среднее | Мгновенное Telegram-уведомление оператора — человек подключается лично |
| Публичная форма = расход токенов на спам | Высокое для демо | Токенизированный демо-лимиттер (квота 5/сессию, 3 уровня) — см. `SECURITY_NOTES.md` §4 |
| GigaChat TLS (dev `ssl.CERT_NONE`) | Низкое (демо) | `GIGACHAT_CA_BUNDLE` на production (см. `EXTERNAL_PROVIDERS.md`) |
| Парсинг защищённых витрин | Блокирует сценарий | Не целевая область — только свои сайты / официальные API |

## 🧭 9. Следующие шаги для коммерциализации

- Адаптировать источник данных (сайт заказчика / API продавца) + промпт под tone-of-voice бренда.
- Подобрать `DEMO_MAX_REQUESTS_PER_SESSION` под допустимый расход на публичном демо.
- На production: CA-bundle для GigaChat, уникальные токены, резервное копирование БД.
- При росте объёмов — схлопывание execution-tracing в один POST (см. `PROJECT_STATE.md` §7).

## ⚖️ 10. Две рамки позиционирования

### 📌 10.1. Рамка 1 — портфельный актив

Проект как есть — готовая демонстрация паттерна для портфолио: живое публичное
демо, операторская панель, воспроизводимое развёртывание (Deployment Validation
пройдена). Ценность — показываю способность delivered end-to-end AI-автоматизацию
с observability и демо-RBAC, а не только скрипт.

**Архитектура под рамку:** единый compose (db + site + worker), `/admin`
runtime-config, три контура observability, демо-стандарт входа + сессионные
лимиты, промпт-файл-SOT — всё, что делает демо «живым», а не статичной картинкой.

### 🏗️ 10.2. Рамка 2 — развёртываемая база под клиентские внедрения

Та же архитектура как заготовка: источник данных меняется (свой сайт / API
продавца / форма обратной связи), промпт адаптируется под brand voice, провайдер
переключается в runtime. Observability, демо-RBAC, лимиттер и fallback остаются
без переделки — это и есть ценность «от базы»: не собирать заново то, что уже
работает.
