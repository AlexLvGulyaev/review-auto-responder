## 💬 Публичный сайт

Контур посетителя: оставляет отзыв, видит автономный AI-ответ, исчерпывает квоту.

## 🏷️ 2. Демо-сессия и квота

**Участники:** анонимный посетитель.
**Цель:** получить короткоживущий демо-токен с квотой на публикации.

**Шаги:**

1. Откройте сайт отзывов `http://localhost:8000/` (инкогнито — свежая квота).
2. У формы отзыва появляется бейдж «Демо: осталось 5 из 5».

**Ожидаемый результат:** браузер получил демо-токен (`localStorage`), бейдж квоты
активен. 1 публикация = 1 LLM-генерация; квота списывается до создания отзыва.

![Форма отзыва с демо-бейджем «Демо: осталось 5 из 5»](screenshots/RAR_site_demo_badge.png)

*Бейдж квоты у формы отзыва — посетитель видит остаток демо-сессии.*

## 📝 3. Оставить отзыв разной тональности

**Участники:** посетитель.
**Цель:** отправить отзыв и получить автономный ответ ИИ.

**Шаги:**

1. Заполните форму: имя и текст (позитивный / негативный / нейтральный).
2. Нажмите «Отправить». Бейдж квоты уменьшится («осталось 4 из 5»).
3. Дождитесь цикла опроса воркера (несколько секунд).

**Ожидаемый результат:** отзыв опубликован в треде; воркер определил тон
(словарём, без LLM) и сгенерировал ответ от `AI Support` как дочерний комментарий;
статус отзыва — `processed`.

![Тред отзывов: посетитель пишет, AI Support отвечает в той же ветке](screenshots/RAR_site_thread.png)

*Публичный сайт: форма слева, тред с отзывами и ответами AI Support справа.*

![Отзыв опубликован, бейдж квоты уменьшился, рядом — ответ AI](screenshots/RAR_site_review_posted.png)

*После отправки: бейдж «4 из 5», отзыв в треде, ответ AI Support сгенерирован.*

> 📌 Тон определяется **словарём маркеров без LLM** — это экономит токены.
> Нейросеть включается только на генерации ответа.

## 🚫 4. Исчерпание демо-квоты

**Участники:** посетитель.
**Цель:** увидеть блокировку формы при исчерпании квоты.

**Шаги:**

1. Отправьте 5 отзывов (квота списывается, бейдж доходит до «0 из 5»).
2. Попробуйте отправить 6-й.

**Ожидаемый результат:** 6-я публикация → `429`; форма блокируется, бейдж
показывает «Лимит демо-сессии исчерпан», предложение обновить страницу для новой
сессии. Backend — единственный SOT квоты; UI лишь отображает состояние.

![Исчерпание демо-квоты: форма заблокирована, бейдж 0 из 5](screenshots/RAR_site_quota_exhausted.png)

*Исчерпание квоты: форма заблокирована, посетитель обновляет страницу для новой сессии.*

## 🔐 5. Вход: полный доступ и демо-режим

**Участники:** оператор (или посетитель для демо-входа).
**Цель:** войти в `/admin` одним из двух путей.

**Шаги:**

1. Откройте `http://localhost:8000/admin` → страница входа (AIP Dark).
2. **Полный доступ:** введите `ADMIN_TOKEN` → конфиг-консоль, бейдж «🛠 Администратор», кнопка «Сохранить» активна.
3. **Демо-доступ (без токена):** кнопка «👁 Войти в демо-режим (только просмотр)» → сервер ставит cookie с `ADMIN_DEMO_TOKEN` (токен не попадает в браузер) → бейдж «👁 Демо-режим», кнопка сохранения отключена.

**Ожидаемый результат:** оба пути ведут в `/admin`; в демо-режиме мутации
блокируются на backend (`POST /admin` → `403`). Если `ADMIN_DEMO_TOKEN` не задан —
кнопка показывает «Демо-вход отключён».

![Вход в /admin: два пути — форма полного токена и одно-кликовой демо-вход](screenshots/RAR_admin_login.png)

*Страница входа в операторскую панель: полный токен или одно-кликовой демо-вход.*

## 🛡️ 6. Демо-RBAC: мутация блокируется на backend

**Участники:** посетитель в демо-режиме.
**Цель:** убедиться, что demo-токен не может менять конфигурацию.

**Шаги:**

1. Войдите демо-кнопкой (сценарий §5).
2. Откройте конфиг-консоль — карточки провайдеров и промпт видны (read-only).
3. Попытка сохранить через UI отключена. Прямой `POST /admin` с demo-токеном
   подтверждает guard → `403`.

**Ожидаемый результат:** `403`. Backend — единственный реальный guard: UI лишь
отключает кнопку, но защита — на сервере. Детали эндпоинта — [🔌 `API_CONTRACT.md` §2](API_CONTRACT.md), [🎛️ `OPERATOR_GUIDE.md` §1](OPERATOR_GUIDE.md).

![/admin под демо-входом: role-бейдж «Демо-режим», кнопка сохранения отключена](screenshots/RAR_admin_demo_view.png)

*Демо-режим: role-бейдж в сайдбаре, кнопка сохранения отключена; мутации → 403 на backend.*

## 🎛️ 7. Смена провайдера и модели без рестарта

**Участники:** оператор (полный доступ).
**Цель:** переключить активный LLM-провайдер в runtime.

**Шаги:**

1. Войдите полным токеном (сценарий §5).
2. В панели «Настройки LLM и провайдера» выберите **Активный провайдер** (`openai`/`gigachat`) и **Fallback**.
3. В карточках провайдеров задайте per-провайдер **Model**, **Temperature**, **Max tokens**, чекбокс **Включён**.
4. Нажмите **Сохранить** (в хидере консоли) → `?saved=1`.
5. Оставьте новый отзыв (сценарий §3).

**Ожидаемый результат:** воркер подхватит новый конфиг на следующем цикле — без
рестарта контейнера. Ответ сгенерирован через активный LLM; при сбое активного —
fallback LLM, затем словарные шаблоны.

![Конфиг-консоль /admin: карточки провайдеров, промпт, ряд «Состояние системы»](screenshots/RAR_admin_config.png)

*Конфиг-консоль: две панели side-by-side (провайдеры | промпт), карточки с параметрами, ряд состояния.*

## ✅ 8. «Проверить» — real-тест провайдера

**Участники:** оператор (полный доступ).
**Цель:** проверить доступность LLM-провайдера без передачи ключей на сайт.

**Шаги:**

1. В конфиг-консоли нажмите **Проверить** на карточке провайдера.
2. Сайт проксирует запрос во внутренний test-API воркера (`POST /provider-test`,
   порт не публикуется на хост, защищён `X-Worker-Token`); воркер делает
   1-токенный real-вызов LLM.
3. Появляется toast-flash результата: «GigaChat: готов, 474мс, 25ток» (или ошибка).

**Ожидаемый результат:** ключи LLM остаются **только на воркере** — публичный
сайт их не получает. Событие пишется в аудит (`admin.provider_test`). Demo → `403`.

![Toast-результат real-теста провайдера: готов, latency, токены](screenshots/RAR_admin_provider_test.png)

*«Проверить»: toast-flash с latency и токенами — ключи не покинули воркер.*

## 📝 9. Правка промпта в runtime

**Участники:** оператор (полный доступ).
**Цель:** изменить тон/стиль ответа без деплоя.

**Шаги:**

1. Войдите полным токеном. В панели «Системный промпт» отредактируйте текст.
2. Нажмите **Сохранить** — `system_prompt.md` на shared volume атомарно
   перезаписывается (файл-SOT).
3. Оставьте новый отзыв (сценарий §3).

**Ожидаемый результат:** воркер подхватит новый промпт по mtime на следующем
цикле — без рестарта. Новый отзыв получит ответ уже по изменённому промпту.
Аудит фиксирует `prompt_len` и `prompt_changed` (без полного текста).

![Смена системного промпта: правка и сохранение в system_prompt.md](screenshots/RAR_admin_prompt_change.png)

*Правка промпта в /admin — сохранение перезаписывает файл-SOT на shared volume.*

![Эффект смены промпта: новый ответ уже по изменённому промпту](screenshots/RAR_admin_prompt_applied.png)

*После применения: новый отзыв получает ответ по изменённому промпту, рестарт не нужен.*

> 📌 При первом запуске воркер копирует вшитый `worker/prompts/v1/system.md` в
> `/data/runtime/system_prompt.md` (bootstrap); дальше единственный SOT — файл.

## 📊 10. Состояние системы

**Участники:** оператор (любой доступ).
**Цель:** увидеть живую картину работоспособности.

**Шаги:**

1. Откройте `/admin` — блок «Состояние системы» вверху (ридонли).
2. Или `GET /admin/status` (JSON): общий статус, проба БД (живой запрос + latency),
   метрики (отзывы new/processed, трейсы ok/error, аудит-счётчик), liveness
   воркера, статус провайдеров.

**Ожидаемый результат:** общий статус `ok`/`degraded`; liveness = `last_iteration_at`
свежее `3 × poll_interval`; булевы флаги «провайдер сконфигурирован» (без секретов).

## 📜 11. Логи обработки (`/admin/executions`)

**Участники:** оператор (любой доступ).
**Цель:** разобрать трассу обработки отзыва.

**Шаги:**

1. Откройте `/admin/executions` — master-detail «Запрос → Ответ».
2. Слева: фильтры (период/статус/тон) + поиск по `review_id` + карточки (7/стр).
3. Выберите карточку — справа: «Цепочка этапов» (получен отзыв → классификация →
   Telegram → генерация LLM → сохранение → отметка обработано), диалектическая пара
   «Запрос пользователя» / «Ответ системы», параметры исполнения (провайдер/модель/
   токены/latency), таймлайн, JSON-снимок.
4. Стрелки ↑/↓ перебирают записи без перезагрузки; deep-link `/admin/executions/{id}`.

**Ожидаемый результат:** шаг LLM-вызова несёт метрики провайдера (модель, длительность,
токены, fallback-причина) — структура полей в [🏗️ `ARCHITECTURE.md` §7](ARCHITECTURE.md).
При падении воркера остаётся `started`-сессия (диагностический признак).

![Консоль /admin/executions: master-detail «Запрос → Ответ», цепочка этапов](screenshots/RAR_admin_executions.png)

*Логи: master-detail — список обработок слева, цепочка этапов и Запрос/Ответ справа.*

![Страница детализации одной обработки](screenshots/RAR_admin_execution_detail.png)

*Deep-link детализации: полная трасса пайплайна одного отзыва.*

## 📋 12. Аудит (`/admin/audit`)

**Участники:** оператор (любой доступ).
**Цель:** просмотреть журнал admin/security-событий.

**Шаги:**

1. Откройте `/admin/audit` — master-detail.
2. Слева: фильтры (период/тип действия/тип ресурса — select-списки) + поиск по
   `user_id`, карточки (7/стр).
3. Выберите запись — справа: параметры действия, исполнитель, metadata, JSON-снимок
   состояния. Deep-link `/admin/audit/{id}`.

**Ожидаемый результат:** события `admin.login_success` (admin/demo), `admin.config_update`,
`admin.provider_test`, `admin.rbac_denied`, `auth.worker_denied`. Секреты и полный
текст промпта в аудит не пишутся (только `prompt_len`, `prompt_changed`, `changed_keys`).

## 📨 13. Уведомление оператора о новом отзыве

**Участники:** воркер → оператор (Telegram).
**Цель:** мгновенный сигнал о новом отзыве, особенно негативе.

**Шаги:**

1. При настроенных `TELEGRAM_BOT_TOKEN` + `TELEGRAM_USER_CHAT_ID` оставьте отзыв (сценарий §3).
2. Воркер определяет тон и отправляет уведомление в Telegram.

**Ожидаемый результат:** оператор получает сообщение с текстом отзыва и
тональностью. Этап `telegram` фиксируется в execution-трейсе. Негатив виден
мгновенно — оператор подключается лично там, где автономный ответ не решает вопрос.
Без токена — этап пропускается (система работает без Telegram).

![Telegram-уведомление оператору о новом отзыве с тональностью](screenshots/RAR_tg_review_notification.png)

*Telegram-уведомление: текст отзыва и определённая тональность.*
